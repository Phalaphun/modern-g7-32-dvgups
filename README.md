# modern-g7-32-dvgups

Шаблон Typst для оформления лабораторных, практических, расчётно-графических, курсовых и выпускных квалификационных работ в Дальневосточном государственном университете путей сообщения (ДВГУПС). Настройки шаблона ориентированы на требования ДВГУПС СТ-02-16-17.

Этот репозиторий является форком проекта [typst-gost.ru](https://typst-gost.ru), адаптированным специально для выполнения учебных и выпускных работ в ДВГУПС. Документация исходного проекта полезна для знакомства с общими принципами шаблона, но параметры и поведение этого форка могут отличаться.

## Быстрый старт

### Локальная установка

Typst ищет локальные пакеты в каталоге, заданном переменной среды `TYPST_PACKAGE_PATH`. Эта переменная должна указывать **на корень всего хранилища пакетов**, а не на каталог самого шаблона.

Например, если хранилище находится в `Q:\repos\typst`, шаблон версии `0.2.2` должен иметь следующую структуру:

```text
Q:\repos\typst\
└── local\
    └── modern-g7-32-dvgups\
        └── 0.2.2\
            ├── typst.toml
            ├── src\
            │   ├── export.typ
            │   └── ...
            ├── template\
            ├── README.md
            └── ...
```

Элементы пути имеют фиксированное назначение:

- `Q:\repos\typst` — корень хранилища, который передаётся в `TYPST_PACKAGE_PATH`;
- `local` — пространство имён локальных пакетов и часть импорта `@local/...`;
- `modern-g7-32-dvgups` — имя пакета, совпадающее с `name` в `typst.toml`;
- `0.2.2` — версия пакета, совпадающая с `version` в `typst.toml`;
- `typst.toml` должен лежать непосредственно внутри каталога версии, без дополнительной вложенной папки репозитория.

Создать такую структуру и клонировать release-ветку можно из PowerShell:

```powershell
$typstPackagePath = "Q:\repos\typst"
$packageParent = Join-Path $typstPackagePath "local\modern-g7-32-dvgups"
$packageDirectory = Join-Path $packageParent "0.2.2"

New-Item -ItemType Directory -Force -Path $packageParent
git clone --branch release/0.2.2-rc `
  https://github.com/Phalaphun/modern-g7-32-dvgups.git `
  $packageDirectory
```

Если репозиторий уже загружен, достаточно переместить или скопировать его содержимое в каталог `local\modern-g7-32-dvgups\0.2.2`. После этого задайте корень хранилища для текущего окна PowerShell:

```powershell
$env:TYPST_PACKAGE_PATH = "Q:\repos\typst"
```

Чтобы сохранить переменную для текущего пользователя Windows постоянно:

```powershell
[Environment]::SetEnvironmentVariable(
  "TYPST_PACKAGE_PATH",
  "Q:\repos\typst",
  "User"
)
```

После постоянной установки перезапустите терминал и редактор: уже запущенные процессы не увидят новое значение автоматически. Проверить значение в новом окне PowerShell можно командой:

```powershell
$env:TYPST_PACKAGE_PATH
```

Альтернативно корень хранилища можно передать только одному запуску консольного компилятора, не создавая переменную среды:

```powershell
typst compile --package-path "Q:\repos\typst" main.typ
```

После установки пакет импортируется по пространству имён, имени и версии:

```typst
#import "@local/modern-g7-32-dvgups:0.2.2": (
  abstract,
  appendixes,
  gost,
  long-listing,
  long-table,
  title-templates,
)
```

Для проверки создайте рядом с работой минимальный `main.typ` с этим импортом и выполните `typst compile main.typ`. Если Typst сообщает, что пакет не найден, проверьте следующее:

- `TYPST_PACKAGE_PATH` указывает на `Q:\repos\typst`, а не на `...\local` или `...\0.2.2`;
- файл находится по пути `Q:\repos\typst\local\modern-g7-32-dvgups\0.2.2\typst.toml`;
- имя и версия в импорте совпадают с каталогами и значениями в `typst.toml`;
- после изменения постоянной переменной среды редактор и терминал были перезапущены;
- при создании новой версии используется новый каталог, например `0.2.3`, и такая же версия указана в `typst.toml` и импорте.

### Базовый `gost.with`

Параметры оформления уже имеют значения по умолчанию. В базовом документе не нужно повторять размеры полей, шрифтов, отступов, интервалов, таблиц и листингов. В `gost.with` достаточно выбрать титульный шаблон ДВГУПС и передать данные работы:

```typst
#show: gost.with(
  title-template: title-templates.at("dvgups-default"),

  ministry: (
    [Министерство транспорта Российской Федерации],
    [Федеральное агентство железнодорожного транспорта],
  ),
  university: (
    [Федеральное государственное бюджетное образовательное учреждение],
    [высшего образования],
    [«Дальневосточный государственный университет путей сообщения»],
  ),
  department: "Название кафедры",

  topic: "Тема работы",
  work-type: "курсовая работа",
  discipline: "Название дисциплины",

  specialty-code: "09.03.02",
  variant: 1,
  work-number: 1,
  group: "Название группы",

  student: "Фамилия И.О.",
  advisor: "Фамилия И.О.",
  advisor-position-secondary: "должность, учёная степень",

  city: "Хабаровск",
)
```

`work-type` — обязательный параметр титульного шаблона ДВГУПС. Поддерживаются курсовая работа, курсовой проект, лабораторная работа, практическая работа, реферат и расчётно-графическая работа. Год можно не передавать: по умолчанию используется текущий.

### Базовая структура документа

После подключения `gost.with` документ обычно состоит из реферата, содержания, основной части, списка источников и приложений:

````typst
#abstract(
  "ключевое слово",
  "ещё одно ключевое слово",
)[
  Текст реферата.
]

#outline()

= Введение

Текст введения.

= Название первого раздела

Текст раздела.

== Название подраздела

Текст подраздела.

=== Название пункта

Текст пункта.

#figure(
  image("assets/image.png", width: 70%),
  caption: [Пример рисунка],
) <example-image>

#long-table(
  table(
    columns: (1fr, 1fr),
    table.header([Параметр], [Значение]),
    [Первый параметр], [Первое значение],
    [Второй параметр], [Второе значение],
  ),
  caption: [Пример длинной таблицы],
) <example-long-table>

#long-listing(
  ```typst
  #let greeting = "Hello, world!"
  #print(greeting)
  ```,
  caption: [Пример длинного листинга],
) <example-long-listing>

= Заключение

Текст заключения.

#bibliography("references.bib")

#show: appendixes

= Название первого приложения

Материалы первого приложения.

= Название второго приложения

Материалы второго приложения.
````

`abstract` автоматически формирует строку со статистикой документа, `outline` создаёт содержание, а `appendixes` переключает последующие разделы в режим приложений. Заголовки первого уровня начинаются с `=`, второго — с `==`, третьего — с `===`. Здесь приведены минимальные вызовы рисунка, длинной таблицы и длинного листинга; особенности многостраничных таблиц и листингов разобраны ниже в разделах с параметрами `long-table` и `long-listing`. Метки `<example-image>`, `<example-long-table>` и `<example-long-listing>` позволяют ссылаться на элементы через `@example-image`, `@example-long-table` и `@example-long-listing`.


## Оформление списка литературы и CSL

Список литературы создаётся стандартной функцией Typst:

```typst
#bibliography("references.bib")
```

Пакет автоматически применяет встроенный CSL-стиль `gost-r-7-0-100-2018-numeric-alphabetical.csl`. Его исходный файл находится в пакете по пути `src/csl/gost-r-7-0-100-2018-numeric-alphabetical.csl`; копировать CSL в проект работы не требуется. Стиль реализует числовые ссылки и оформление библиографического списка по ГОСТ Р 7.0.100–2018. Источники сортируются сначала по языковой группе, затем по автору или заглавию и году.

### Поддерживаемые типы записей

Typst сначала преобразует записи BibLaTeX из `references.bib` во внутреннюю модель CSL. Используемый стиль содержит отдельные правила для следующих типов CSL:

| Тип BibLaTeX | Тип CSL | Что описывает |
|---|---|---|
| `@book` | `book` | Книга или отдельное издание. |
| `@inbook`, `@incollection` | `chapter` | Глава или раздел книги. |
| `@article` | `article-journal` | Статья в научном журнале. |
| `@article` с соответствующими данными издания | `article-magazine`, `article-newspaper` | Статья в журнале общего профиля или газете. |
| `@inproceedings` | `paper-conference` | Доклад или статья в материалах конференции. |
| `@thesis`, `@mastersthesis`, `@phdthesis` | `thesis` | Диссертация или выпускная работа. |
| `@online` | `webpage` | Сайт, веб-страница или другой удалённый электронный ресурс. |
| Запись энциклопедической статьи | `entry-encyclopedia` | Статья из энциклопедии или справочника. |

Точное преобразование типа выполняет библиографический модуль Typst.

CSL использует следующие основные поля записи:

- `author`, `editor`, `translator` — авторы, редакторы и переводчики;
- `title`, `shorttitle` — полное и сокращённое заглавие;
- `journaltitle`, `booktitle`, `series` — журнал, сборник или серия;
- `publisher`, `location`, `institution` — издатель, место издания или организация;
- `date` или `year`, а также `volume`, `number`, `edition`, `pages`, `pagetotal` — выходные данные;
- `url`, `urldate`, `doi` — данные электронного ресурса и дата обращения;
- `langid` — язык источника, используемый при локализации и сортировке.

Для интернет-источника обязательно заполняйте `url` и желательно `urldate`, иначе дата обращения не появится в описании.

### Ограничение определения языка

В используемом CSL язык определяется по факту наличия поля `language`: пустое поле означает русскоязычный источник, а заполненное — иностранный. Поэтому для русскоязычных записей в этом шаблоне рекомендуется **не указывать** `langid`; для иностранных записей используйте, например, `langid = {english}`.

В некоторых версиях Typst/Hayagriva встречались проблемы с преобразованием `langid` BibLaTeX в поле `language` CSL. Из-за этого источник мог получить неправильные обозначения (`С.`/`p.`, `и др.`/`et al.`) или оказаться не в той языковой группе при сортировке. После обновления Typst проверяйте итоговый PDF: обработка языка зависит одновременно от версии библиографического движка и правил этого CSL-файла.

## Параметры шаблона

Значения по умолчанию хранятся во внутренних константах `src/constants.typ`. Пользователю не требуется импортировать эти константы напрямую: глобальные настройки передаются в `gost.with`, а настройки отдельной длинной таблицы или листинга — в `long-table` и `long-listing`.

В колонке «Публичный параметр» прочерк означает, что значение пока можно изменить только в исходном коде пакета. Внутренние константы не являются стабильным публичным API и могут быть переименованы между версиями.

| `default-contents-heading-margin-bottom` | `default-leading` | `contents-heading-margin-bottom` | Расстояние после заголовка содержания до первой строки оглавления. |

### Настройка отдельной длинной таблицы

Аргументы `long-table` переопределяют глобальные значения только для конкретной таблицы:

```typst
#long-table(
  table(...),
  caption: [Название таблицы],
  caption-gap: 6pt + 1mm,
  continuation-gap: 16pt - 2mm,
  ending-gap: 16pt - 2mm,
  continuation-indent: 0pt,
  ending-indent: 0pt,
)
```

| Аргумент `long-table` | Назначение |
|---|---|
| `caption-gap` | Расстояние после обычного названия таблицы. |
| `continuation-gap` | Расстояние после строки «Продолжение таблицы». Значение `auto` использует `long-table-continuation-gap` из `gost.with`. |
| `ending-gap` | Расстояние после строки «Окончание таблицы». Значение `auto` использует `long-table-ending-gap` из `gost.with`. |
| `continuation-indent` | Отступ строки «Продолжение таблицы». Значение `auto` использует `long-table-continuation-indent` из `gost.with`. |
| `ending-indent` | Отступ строки «Окончание таблицы». Значение `auto` использует `long-table-ending-indent` из `gost.with`. |

Название длинной таблицы является частью её первой повторяемой служебной строки, поэтому оно переносится на следующую страницу вместе с шапкой и первой доступной строкой таблицы. На последующих страницах эта же строка отображает «Продолжение таблицы» или «Окончание таблицы». Для PDF при этом сохраняется одна нативная семантическая подпись `figure.caption`; визуальная копия и повторяемые названия помечаются как артефакты. Счётчик, ссылки и статистика реферата по-прежнему относятся к одной фигуре. Обычные таблицы и рисунки этим механизмом не затрагиваются.

### Настройка отдельного длинного листинга

Аргументы `long-listing` переопределяют глобальные значения только для конкретного листинга:

```typst
#long-listing(
  raw("код", lang: "text", block: true),
  caption: [Название листинга],
  caption-gap: 6pt + 1mm,
  continuation-gap: 16pt - 2mm,
  ending-gap: 16pt - 2mm,
  continuation-indent: 0pt,
  ending-indent: 0pt,
)
```

| Аргумент `long-listing` | Назначение |
|---|---|
| `caption-gap` | Расстояние после обычного названия листинга. |
| `continuation-gap` | Расстояние после строки «Продолжение листинга». Значение `auto` использует `long-listing-continuation-gap` из `gost.with`. |
| `ending-gap` | Расстояние после строки «Окончание листинга». Значение `auto` использует `long-listing-ending-gap` из `gost.with`. |
| `continuation-indent` | Отступ строки «Продолжение листинга». Значение `auto` использует `long-listing-continuation-indent` из `gost.with`. |
| `ending-indent` | Отступ строки «Окончание листинга». Значение `auto` использует `long-listing-ending-indent` из `gost.with`. |
| `line-vertical-inset` | **Устаревший аргумент.** При явной передаче переопределяет верхнее и нижнее поля строк в прежнем формате. Без него используются глобальные параметры `long-listing-line-inset`, `long-listing-line-leading` и `long-listing-line-min-height`. |

Название длинного листинга является частью его первой повторяемой служебной строки и переносится вместе с рамкой и первой доступной строкой кода. На следующих страницах служебная строка отображает продолжение или окончание. В PDF остаётся одна нативная семантическая подпись `figure.caption`, а её визуальная копия и повторяемые названия являются артефактами. Счётчик и PDF-ссылка продолжают указывать на единственный объект. Обычные листинги и рисунки этим механизмом не затрагиваются.
